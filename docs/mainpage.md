# QuantLab

Небольшая библиотека C++17 для анализа финансовых временных рядов. Проект
демонстрирует полный инженерный цикл: CMake, unit-тесты, измерение
производительности, документирование API и автоматическую публикацию.

Исходный код: <https://github.com/Mu-ggle/quantlab-cpp>.

## Возможности и математические определения

Все функции объявлены в `quantlab/analytics.hpp` в пространстве имен `quantlab`.
Цены передаются в хронологическом порядке; входные векторы не изменяются.

| Функция | Результат | Ограничения |
| :--- | :--- | :--- |
| `quantlab::simple_returns` | Простые доходности `r[i] = p[i+1] / p[i] - 1`; длина `n-1` | Не менее двух положительных конечных цен |
| `quantlab::moving_average` | Среднее каждого полного окна; длина `n-window+1` | Конечные значения; `1 <= window <= n` |
| `quantlab::sample_volatility` | Выборочное стандартное отклонение, умноженное на `sqrt(periods_per_year)` | Не менее двух конечных доходностей; конечное положительное число периодов |
| `quantlab::maximum_drawdown` | Максимум `(peak - price) / peak`, где `peak` - достигнутый к этому моменту максимум | Непустой ряд положительных конечных цен |

Для волатильности используется выборочная дисперсия
`sum((r[i] - mean)^2) / (n - 1)`. Значение `periods_per_year` по умолчанию
равно 252. Это параметр частоты данных: для других частот его нужно задать
явно. Функция не оценивает частоту и не проверяет календарные интервалы.
Годовое масштабирование по квадратному корню является принятой модельной
конвенцией, а не гарантией свойств наблюдаемого ряда.

Просадка возвращается как доля: `0.20` означает 20%. Один элемент,
постоянный или неубывающий ряд цен дают нулевую просадку. Скользящее среднее
с окном 1 воспроизводит исходный ряд; неполные начальные окна не выдаются.

Неправильные аргументы приводят к `std::invalid_argument`. Если результат
не представим конечным `double`, выбрасывается `std::overflow_error`.
Точные контракты описаны рядом с объявлениями функций.

## Пример использования

```cpp
#include <quantlab/analytics.hpp>
#include <iostream>
#include <vector>

int main() {
    const std::vector<double> prices{100.0, 110.0, 99.0};
    const auto returns = quantlab::simple_returns(prices);
    const auto averages = quantlab::moving_average(prices, 2);
    std::cout << returns.at(0) << '\n';                  // 0.1
    std::cout << averages.at(0) << '\n';                 // 105
    std::cout << quantlab::maximum_drawdown(prices) << '\n'; // 0.1
    std::cout << quantlab::sample_volatility(returns, 1.0) << '\n';
}
```

Подключайте цель `QuantLab::quantlab` через `target_link_libraries`, чтобы CMake
передал пути заголовков и требование C++17 потребителю библиотеки.

## Сборка и проверки

Необходимы CMake 3.22 или новее и компилятор с поддержкой C++17. При первой конфигурации
CMake загружает закрепленные версии doctest и Google Benchmark, поэтому
нужен доступ в интернет.

```text
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release --parallel
ctest --test-dir build -C Release --output-on-failure
```

На Linux и с одноконфигурационными генераторами:

```text
./build/quantlab_demo
./build/benchmarks/quantlab_benchmark --benchmark_min_time=0.05s
```

На Windows с Visual Studio исполняемые файлы находятся в
`build/Release/quantlab_demo.exe` и
`build/benchmarks/Release/quantlab_benchmark.exe`. При использовании MinGW
они находятся непосредственно в `build` и `build/benchmarks`.

Для MinGW задайте генератор явно в отдельном каталоге:

```text
cmake -S . -B build-mingw -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release
cmake --build build-mingw --parallel
ctest --test-dir build-mingw --output-on-failure
```

Старые Windows-инструменты могут некорректно обрабатывать Unicode в путях.
В таком случае используйте путь из ASCII-символов, например
`C:\dev\quantlab-cpp`, и новый каталог сборки. Смена генератора в уже
настроенном каталоге сборки не поддерживается.

Тесты проверяют известные численные ответы, граничные случаи, устойчивость
вычислений и отклонение некорректных данных. Бенчмарк измеряет все четыре
функции на детерминированных данных нескольких размеров. Генерация входа
не входит в измеряемую часть, а результаты защищены от удаления оптимизатором.
Возвращаемые векторы создаются внутри функций, поэтому их выделение памяти
входит в стоимость соответствующих операций.

## Автоматизация

Workflow `.github/workflows/ci.yml` выполняет сборку, запускает тесты и
бенчмарк, а также генерирует документацию Doxygen. Результаты измерений
видны в журнале CI. Документация публикуется в GitHub Pages из ветки
`main` после успешного завершения проверок. Для публикации в настройках репозитория источником Pages должен
быть выбран GitHub Actions.

Сайт: <https://Mu-ggle.github.io/quantlab-cpp/>.

Локальная генерация документации требует установленного Doxygen:

```text
cmake -S . -B build -DQUANTLAB_BUILD_DOCS=ON
cmake --build build --target docs
```

Откройте `build/docs/html/index.html`. Предупреждения Doxygen считаются
ошибками и останавливают проверку документации.

Для первичной публикации из PowerShell 7 предусмотрен скрипт:

```text
gh auth login --hostname github.com --git-protocol https --web --scopes workflow
pwsh -File scripts/publish.ps1 -Owner YOUR_LOGIN
```

Он предназначен для создания публичного репозитория, настройки ссылок и
Pages, отправки проекта и проверки CI. `YOUR_LOGIN` замените своим GitHub
login. До выполнения скрипта ссылки на репозиторий и сайт являются шаблонами.

## Вычислительная стоимость

Все четыре алгоритма линейны по числу входных элементов. Скользящее
среднее обновляет компенсированную сумму окна. Для волатильности метод
Уэлфорда применяется к центрированным и масштабированным данным, после
чего восстанавливается исходный масштаб. Это снижает риск переполнения
при вычислении квадратов и потери точности при большом общем смещении;
обычная погрешность вычислений с плавающей точкой сохраняется.
Доходности и средние требуют память под выходной вектор; волатильность и
максимальная просадка используют постоянную дополнительную память.

Абсолютные времена зависят от процессора, ОС, компилятора и нагрузки.
Измерения на общих CI runners предназначены для воспроизводимой
демонстрации работы benchmark, а не для строгого сравнения разных машин.

## Использование ИИ

Проект подготовлен с помощью ИИ по условию домашнего задания. Настройка
агента находится в `AGENTS.md`; правила задают структуру проекта,
команды проверки и ограничения на изменения. Обучающийся должен уметь
объяснить API, используемые формулы и последовательность CI по коду
и сохраненным журналам запуска.
